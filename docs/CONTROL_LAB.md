# ห้องทดลองควบคุมงาน — ใช้เวลา 10–15 นาที

เป้าหมายคืออธิบายให้ได้ว่า **ใครตัดสินใจอะไร กับข้อมูล revision ไหน เพื่ออะไร และอ้างหลักฐานใด** ชื่อโฟลเดอร์เป็นเพียงส่วนหนึ่งของการจัดเก็บ

## 1. ลองทางลัดก่อน (3 นาที)

เปิด `index.html` แล้วเลือกเคส 01

1. เปลี่ยนตำแหน่งจัดเก็บเป็น PUBLISHED สังเกตว่าสถานะข้อมูลยังเป็น WIP
2. เลือกหัวหน้าหน้างาน แล้วกดตรวจใช้หน้างาน อ่านเหตุผลที่ถูกหยุด
3. เลือกผู้ดูแล CDE แล้วกดขออ่านข้อมูล สังเกตว่าการดูแลระบบไม่ได้เปิดข้อมูลทุกชุดในนโยบายนี้

ถามทีม: ในงานของเรา ทางลัดแบบนี้ยังเกิดขึ้นได้ผ่านช่องทางใด?

## 2. ทำให้ผ่านด้วยผู้รับผิดชอบและหลักฐาน (4 นาที)

1. หัวหน้าสถาปนิก → บันทึกผลตรวจภายใน → อนุญาตแชร์
2. ผู้ประสาน BIM → บันทึกผลประสาน
3. Document Controller → ส่งขออนุมัติ
4. ผู้อนุมัติที่ได้รับมอบหมาย → อนุมัติเพื่อวัตถุประสงค์ที่ระบุ
5. Document Controller → ออกเอกสารควบคุม
6. หัวหน้าหน้างาน → ใส่ revision ให้ตรง → ตรวจใช้หน้างาน

ผลที่ผ่านหมายถึงผ่านจุดควบคุมข้อมูลของแบบจำลอง ไม่ได้ยืนยันเงื่อนไขพร้อมเริ่มงานทั้งหมดในโครงการจริง การคลิกบันทึกผลตรวจในตัวอย่างใช้แทนผลตรวจสมมติ ไม่ใช่การตรวจแบบจริง

## 3. เปลี่ยนเงื่อนไขแล้วดูผล (4 นาที)

- ทดลองออกเพื่อ coordination แทน construction: แม้อยู่ Published ก็ยังนำไปใช้ก่อสร้างไม่ได้
- หลังออกเอกสาร ให้ผู้ออกแบบ ARC เปิด revision ใหม่: หลักฐานปัจจุบันถูกยกเลิก แต่ชุดออกก่อนหน้ายังอยู่ในประวัติ
- เคส 02 มี change notice กำหนด Hold R01 ขณะทบทวน R02 หลังออก R02 แล้ว ลองตรวจใช้ R01 ก่อนเปลี่ยนเป็น R02
- เคส 03: Admin/BIM ขออ่าน Commercial ไม่ผ่าน; Commercial และผู้อนุมัติฝั่ง Owner อ่านได้ การย้ายโฟลเดอร์ไม่เปลี่ยนรายชื่อผู้รับในแบบจำลองนี้

การ Hold ทุก revision เป็น **นโยบายเฉพาะของเคส** ไม่ใช่กฎทั่วไปหรือข้อบังคับ ISO สิทธิ์บนระบบจริงอาจเปลี่ยนตามโฟลเดอร์ปลายทางและ inheritance ต้องทดสอบเพิ่มเติม

## 4. ทบทวนการควบคุมพฤติกรรมการทำงาน (3 นาที)

เปิดหัวข้อ “ถ้าคนส่งแบบทางแชตข้ามระบบล่ะ?” แล้วบันทึกคำตอบท้ายหน้า

| ประเด็น | สิ่งที่ทีมต้องระบุให้ชัด |
| --- | --- |
| ป้องกัน | ช่องทางออกเอกสาร ผู้มีสิทธิ์ออก ผู้อนุมัติ และขอบเขตผู้รับ |
| ตรวจพบ | ใครตรวจ revision ที่หน้างานถือ เทียบกับทะเบียนใด และเมื่อไร |
| ตอบสนอง | ใครสั่ง Hold/ถอนชุด ใครแจ้งผู้ได้รับผลกระทบ ใครยืนยันว่าเปลี่ยนฉบับครบ |
| หลักฐาน | revision, intended use, ผลตรวจ, ผลอนุมัติ, เลขออกเอกสาร, ผู้รับ และเวลาที่เกี่ยวข้อง |

กดดาวน์โหลดสรุปสำหรับคุยกับทีม หรือ Export ผลทดลอง JSON เพื่อกลับมาลองต่อ

## ขอบเขต

- ไฟล์ ชื่อบทบาท นโยบาย และผลตรวจทั้งหมดสมมติ ข้อตกลงจริงต้องมาจาก appointments และกติกาโครงการ
- สลับบทบาทได้โดยไม่ยืนยันตัวตน จึงใช้บังคับสิทธิ์จริงไม่ได้
- ประวัติเป็นบันทึกการเรียนรู้ในเครื่อง แก้ไข/ล้างได้ ไม่ใช่ audit log ที่ป้องกันการแก้ไข
- ไม่มีการเชื่อมต่อ ACC ไม่มีการส่งข้อมูลหรือ analytics และไม่มีใบรับรองมาตรฐาน
- รุ่นนี้ยังไม่จำลอง delegates, rejected/conditional approvals, retention rules หรือ permission inheritance เต็มระบบ
- หลักคิด: หากไม่มีคนรับผิดชอบจุดควบคุม ไม่มีหลักฐาน และไม่มีวิธีตรวจว่าคนใช้ฉบับถูก โฟลเดอร์อย่างเดียวไม่พอ
